## Текущий статус проекта
Мы разработали фундамент для Flora:
1. **Скелет и структура проекта в Docker** (`Dockerfile`, `docker-compose.yml`, `requirements.txt`).
2. **База данных памяти (SQLite)** в `app/database.py` (поддерживает мультиарендность/multi-tenancy, сохраняет историю диалогов, факты о пользователях, информацию о стартапах и уроки/рефлексии — всё строго изолировано по `user_id`).
3. **Личность и Brain** в `app/brain.py` (системный промпт Claude 3.5 Sonnet / GPT-4o, объединяющий роли любящей девушки и технического CTO. Логика динамически адаптирует доступные инструменты и системную инструкцию в зависимости от текущего тарифа пользователя).
4. **Telegram-интерфейс 24/7** в `app/bot.py` на базе `aiogram` (обработка диалогов, команды `/start`, `/clear`, `/status`. Реализованы авто-блокировка неактивных пользователей без подписки, лимитирование запросов в день по тарифным планам, а также гибкие команды администрирования планов `/admin_set_plan`, `/admin_usage`, `/admin_disable` для владельца).
5. **Распознавание голосовых сообщений (STT)** в `app/tools/voice_processor.py` (интеграция конвертера `ffmpeg` и OpenAI Whisper API, чтобы Flora умела «слышать» ваши голосовые сообщения в Telegram).
6. **Автоматический Web-браузер (Playwright)** в `app/tools/browser_tool.py` (позволяет Flora самостоятельно заходить на сайты, считывать тексты, регистрироваться, заполнять формы и собирать информацию для стартапа).
7. **Автоматический Деплой (CI/CD)** в `.github/workflows/deploy.yml` (авто-обновление бота на сервере при каждом пуше в твой GitHub репозиторий).
8. **Бекап Owner-версии**: Полная оригинальная "Owner"-версия кода со всеми инструментами и без ограничений продублирована в папку `owner/` как резервная копия.

## 🗺️ Реализованные этапы монетизации и тарифов (Phase B: Sellable Core)
- **Изоляция данных по `user_id`**: Вся долгосрочная память (факты, стартапы, рефлексия) переведена на мультиарендную схему.
- **Тарифный Gate на инструменты**: На уровне ядра агента Flora жестко контролируется доступ к инструментам. Starter-пользователи имеют доступ только к беседе и долгосрочной памяти, Pro-пользователи получают доступ к интернет-серфингу, Business — к чтению Git-репозиториев, а Owner — ко всему спектру инструментов (запуск терминала, генерация SSH, коммиты, запись файлов).
- **Лимиты сообщений**: Бот автоматически считает отправленные сообщения и блокирует отправку при превышении дневных ограничений (например, 80 для Starter, 150 для Pro, 300 для Business).
- **Subscription Gate**: Если у пользователя нет активной подписки (план `none` или статус `inactive`), бот вежливо отказывает в доступе и предлагает выбрать тарифный план. Владельцы из `ALLOWED_USER_IDS` автоматически получают статус `owner` с неограниченным доступом.

### Этап 3: Инструменты Git и Индексация Кода (ChromaDB)
*Нам нужно научить Flora подключаться к твоим репозиториям и "понимать" структуру кода.*
1. **Создать `app/tools/git_tool.py`**:
   - Написать класс `GitManager` с методами: `clone_repo(url)`, `create_branch(name)`, `commit_and_push(message)`.
2. **Создать `app/tools/code_indexer.py`**:
   - Настроить ChromaDB для семантического поиска.
   - Реализовать парсер файлов проекта (чтение кода, разбиение на чанки и запись векторов).
3. **Зарегистрировать инструменты в `FloraBrain`**:
   - Реализовать агентский цикл (ReAct), чтобы Flora могла сама решать: "О, меня попросили найти баг, сначала я воспользуюсь инструментом поиска по коду, а потом инструментом создания коммита".

### Этап 4: Запуск проектов в Docker-песочнице (Sandbox Runner)
*Научим Flora разворачивать проекты прямо на сервере и выдавать рабочую ссылку.*
1. **Создать `app/tools/runner.py`**:
   - Интегрировать библиотеку `docker` (docker-py) для безопасного управления контейнерами на VPS.
   - Реализовать автоопределение стека проекта (если есть `package.json` -> Node.js, если `requirements.txt` -> Python).
   - Flora создает временный Docker-контейнер для твоего стартапа, запускает его и пробрасывает свободный порт.
2. **Интегрировать инструмент туннелирования (localtunnel / ngrok или Cloudflare Tunnel)**:
   - Чтобы не открывать порты сервера наружу, Flora запускает быстрый туннель к порту проекта и отправляет тебе публичную веб-ссылку (`https://flora-yourproject.loca.lt`).

### Этап 5: Логика Саморазвития (Self-Reflection Loop)
*Обеспечим Flora возможность становиться умнее с каждым проектом.*
1. **Добавить функцию Reflection**:
   - После завершения деплоя или исправления бага, Flora запускает отдельный скрытый запрос к LLM: *"Проанализируй выполненную задачу, какие ошибки возникли, как мы их решили, какой урок нужно вынести для будущего?"*
   - Полученный урок записывается в `reflection_lessons` в SQLite.
2. **Автоматическое подмешивание опыта**:
   - При каждом новом запросе к ИИ, база последних уроков из SQLite подтягивается в системный промпт (это уже частично реализовано в `app/brain.py`!).

## 🛠️ Как запустить Flora на твоем сервере (Инструкция)

Когда ты получишь VPS-сервер, выполни следующие шаги:

1. **Склонируй этот репозиторий на сервер:**
   ```bash
   git clone git@github.com:pozetiv4iks/flora.git FloraAgent
   cd FloraAgent
   ```

2. **Создай и заполни файл настроек `.env`:**
   ```bash
   cp .env.example .env
   nano .env
   ```
   *Обязательно укажи `TELEGRAM_BOT_TOKEN`, `LLM_API_KEY`, твой `ALLOWED_USER_IDS` (Telegram ID) и `GITHUB_TOKEN`.*

3. **Запусти Flora в Docker:**
   ```bash
   docker compose up -d --build
   ```
   *Все! Flora запустится в фоновом режиме, база данных создастся автоматически, и она напишет тебе приветствие, как только ты нажмешь `/start` в своем Telegram-боте.*

4. **Логи и мониторинг:**
   - Чтобы посмотреть, как Flora себя чувствует:
     ```bash
     docker compose logs -f
     ```

## 🔄 Автоматический деплой при пуше (CI/CD)

Мы настроили интеграцию с **GitHub Actions**. Теперь тебе не нужно каждый раз заходить на сервер по SSH и вручную писать `git pull` и `docker compose up` при обновлении кода. Как только ты делаешь `git push` в свою ветку `master`, GitHub сам автоматически подключается к твоему серверу, стягивает изменения и перезапускает Flora!

### Как это настроить (один раз на GitHub):
1. Перейди в свой репозиторий на GitHub.
2. Открой вкладку **Settings -> Secrets and variables -> Actions**.
3. Нажми **"New repository secret"** и создай следующие три секрета:
   - **`SSH_HOST`** — IP-адрес твоего нового сервера.
   - **`SSH_USERNAME`** — имя пользователя (обычно `root`).
   - **`SSH_KEY`** — приватный SSH-ключ, по которому GitHub будет подключаться к серверу. (Ты можешь использовать тот же приватный ключ от SSH, по которому подключаешься сам, либо сгенерировать отдельный и добавить его публичную часть в файл `~/.ssh/authorized_keys` на сервере).
4. Всё! Теперь любой пуш в ветку `master` автоматически обновит бота на сервере в течение 20-30 секунд! 🚀
